# Accessibility checks

`e2e/a11y.spec.ts` runs axe-core (`@axe-core/playwright`) with the tags `wcag2a`, `wcag2aa`,
`wcag21a`, `wcag21aa` on every page, in the light and the dark theme: audits list (with data and
empty), new audit (also with validation errors), audit detail (running, completed, capped and
degraded, failed), run viewer, review queue (with items, empty, and with the undo notice showing),
sources (audit picker, an audit with gap report, empty audit), source detail (brand found, page
unreadable), evals (with data and empty). `e2e/mobile.spec.ts` also checks the open navigation menu.

**No rule is disabled and no element is excluded.**

Not covered by this automated check (axe finds roughly a third of WCAG problems):

- Screen reader output was never listened to. The aria-live regions are asserted by text and
  attribute only (`progress-announcement`, `review-announcer`).
- Hover, pressed and disabled states, and any state the fixtures do not reach (429 and 503 alerts,
  the "Not saved" failure toast, capped lists with "show all").
- WCAG 2.2 criteria and the AAA level; reflow at 400% zoom; text spacing overrides; forced-colors mode.
- Real keyboard order was tested only for the mobile menu (focus trap, Escape, focus return).

Findings of the first full run: axe reported no violations on any page. The problems found in this
phase came from the 375px checks instead (see the phase notes in the commit message).
